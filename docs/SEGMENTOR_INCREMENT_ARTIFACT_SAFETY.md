# Segmentor implementation increment: fail-safe artifact publication

**Status:** implemented on a dedicated feature branch; not merged or deployed.
**Baseline:** `main` at `643a182272ab9b5d7d12b24068bb88f85a836ff9` (2026-10-17).
**Branch:** `codex/segmentor-safe-artifact-publication-20261017`.

## Scope delivered in this increment

- The inference runner now requires `--intensity-offset` explicitly. The hosted workflow already passes `1024`, so its existing experiment remains reproducible; this change does **not** establish that the offset is correct HU calibration.
- Generated assets are written to a sibling staging directory. The script only publishes that directory after generation and the script's own output-count checks finish. If model inference or generation fails before publication, previously generated assets are left untouched.
- Publication restores the prior directory if installing a completed staged directory fails. A cleanup warning may leave a uniquely named backup after successful publication; it does not silently remove the newly published result.
- The manifest records SHA-256 identities for the exact CT and source labelmap NRRD members, plus UTC generation/inference timestamps, to make output provenance traceable.
- A lightweight Node test invokes the standard-library publication helper to verify successful replacement, rollback on a simulated publication failure, and the explicit preprocessing-argument requirement.
